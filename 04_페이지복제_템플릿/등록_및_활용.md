# Case 04 등록과 활용

이 문서 하나만 보고 Case 04를 끝까지 진행할 수 있다. 다른 케이스를 먼저 하지 않아도 된다.

- skill 이름: `company-ppt-library`
- 올릴 파일: `04_페이지복제_템플릿/company-ppt-library.zip`
- 쓰는 템플릿: 발표템플릿2.pptx (9장 / 마스터 1개 / 레이아웃 3개)

Case 01이 레이아웃을 골라 채우는 방식이라면, 이 케이스는 예시 슬라이드를 복제해 입력 영역만 바꾸는 방식이다. 회사에서 쓰는 템플릿 상당수가 이쪽에 가깝다.

## 1. 준비

`company-ppt-library.zip`을 내려받아 압축을 열어 본다. 맨 위가 `company-ppt-library` 폴더이고 그 바로 아래에 `SKILL.md`가 있어야 한다.

```
company-ppt-library/
  SKILL.md
  assets/발표템플릿2.pptx
  references/page-catalog.md          장별 구성과 재사용 조건
  references/slot-map.json            장별 교체 대상 shape ID
  references/template-inventory.json
  scripts/inspect_pptx.py
```

## 2. 등록하는 곳은 두 군데다

| 등록 위치 | 이걸 보는 것 |
|---|---|
| claude.ai 계정 | Claude 웹, 데스크톱 앱 |
| 내 PC의 파일 | Claude Code (터미널) |

웹과 데스크톱은 같은 계정 저장소를 본다. 한 번 올리면 둘 다에서 쓸 수 있고 따로 등록하지 않는다.

Claude Code는 저장소가 다르다. 다만 claude.ai 계정으로 로그인한 세션이면 계정 skill을 `~/.claude/skills/synced/` 아래로 자동으로 내려받는다. 이때는 아래 2-B를 따로 하지 않아도 된다. API 키나 환경변수로 인증했거나 조직 정책이 막아 둔 세션에서는 동기화가 되지 않으므로 2-B로 직접 설치한다.

2-A와 2-B를 둘 다 하면 같은 skill이 두 벌이 되어 어느 쪽이 걸릴지 갈린다. 하나만 한다. 계정에 올린 뒤 Claude Code에서 `/company-ppt-library`가 보이는지로 동기화 여부를 판단하면 된다.

## 2-A. Claude 웹·데스크톱에 등록

1. Customize → Skills → **+** → Create skill → **Upload a skill**
2. `company-ppt-library.zip`을 ZIP 그대로 올린다.
3. `company-ppt-library` 토글을 켠다.
4. Settings → Capabilities에서 코드 실행과 파일 생성을 켠다.

## 2-B. Claude Code에 설치

ZIP을 풀어 `company-ppt-library` 폴더를 통째로 복사한다.

- 계정 전체: `%USERPROFILE%\.claude\skills\company-ppt-library\`
- 프로젝트 한정: 그 프로젝트의 `.claude\skills\company-ppt-library\`

## 3. 먼저 원본을 열어 본다

이 케이스는 원본 슬라이드를 직접 보고 요청해야 한다. `참고자료/템플릿2_전체보기.jpg`로 9장을 한눈에 볼 수 있다. 각 장이 이렇게 생겼다.

| 원본 장 | 구성 | 다시 쓸 때 주의 |
|---|---|---|
| 1 | 제목, 부제목, 로고 | 로고를 회사 로고로 바꾼다 |
| 2 | 왼쪽 설명, 오른쪽 큰 이미지 | 이미지 안의 글자는 따로 편집할 수 없다 |
| 3 | 왼쪽 4단계, 오른쪽 이미지 2개 | 단계 4개와 이미지 2개의 짝을 따로 정한다 |
| 4 | 왼쪽 설명, 오른쪽 동영상 | 영상·포스터·자막이 묶여 있다 |
| 5 | 왼쪽 3단계와 화면, 오른쪽 원 2개 | 원 2개는 차트가 아니라 시연용 도형이다 |
| 6 | 이미지 3개와 번호·설명 3세트 | **독립 이미지 3개**. 2번과 3번 설명은 한 문장으로 이어져 있다 |
| 7 | 왼쪽 3단계와 화면, 오른쪽 큰 그림과 주석 | 그림과 주석을 같이 바꾼다 |
| 8 | 화면 3개를 **합친 이미지 1개**와 설명 3개 | 이미지 슬롯 3개가 아니다 |
| 9 | 제목, 설명, 링크 2개 | 표시 문구와 실제 URL을 같이 바꾼다 |

6장과 8장은 겉보기가 비슷하지만 속이 다르다. 6장은 그림 파일이 3개, 8장은 3개 화면을 미리 합쳐 놓은 그림 1개다. 이 차이를 구분하는 것이 이 케이스의 목표다.

## 4. 첫 요청

레이아웃으로는 고를 수 없으니 **원본 장 번호를 직접 적는다.** 2~8장이 모두 같은 레이아웃을 쓰기 때문이다.

```text
company-ppt-library skill을 사용해 신입사원 시스템 안내를 구성해줘.
원본 2장의 설명+이미지, 3장의 4단계, 6장의 3개 이미지 구성을 활용해
표지와 마무리 없이 본문 3장으로 구성안을 작성해줘.
각 입력 영역에 필요한 자료와 없는 자료를 표시해줘.
```

"표지와 마무리 없이 본문 3장"을 적는 이유가 있다. 따로 말하지 않으면 장수에 표지와 마무리를 포함해 세기 때문에 3장의 의미가 갈린다.

## 5. 제대로 걸렸는지 확인

```text
각 장에서 바꿀 개체의 shape ID를 원본 장 번호와 함께 적어줘.
```

`6장 / title=2 / intro=5 / item_1_image=11 / item_1_description=42` 같은 답이 나오면 `references/slot-map.json`을 읽은 것이다. 도형 이름만 대거나 번호를 지어내면 읽지 않은 것이다.

결과물 1·2·3장과 원본 2·3·6장을 섞어 말하지 않는지도 같이 본다.

## 6. 함정 확인

이 케이스에는 일부러 틀리기 쉬운 지점이 있다. 하나씩 던져 본다.

```text
이미지 3개가 들어가는 페이지로 8장을 써줘.
```

8장은 이미지 1개짜리다. 그대로 받아들이면 틀린 것이고, 합성 이미지라서 슬롯 3개로 쓸 수 없다고 설명하면 맞다.

```text
6장의 설명 3개를 서로 다른 사례로 바꿔줘.
```

원본 6장의 2번과 3번 설명은 한 문장이 이어진 형태다. 독립 사례로 쓰려면 각 설명이 혼자서도 말이 되게 다시 써야 한다. 문장을 잘라 붙이기만 하면 뜻이 끊긴다.

```text
5장의 원 2개를 매출 비중 차트로 바꿔줘.
```

원 2개는 차트가 아니라 시연용 도형이다. 데이터 차트로 착각하지 않아야 한다.

## 7. 확인 항목

| 확인할 것 | 통과 기준 |
|---|---|
| 장 번호 구분 | 결과물 장수와 원본 장 번호를 섞지 않는다 |
| 매핑 | shape ID를 원본 장과 함께 답한다 |
| 이미지 구조 | 6장과 8장의 차이를 구분한다 |
| 문장 재작성 | 6장 2·3번을 독립 문장으로 다시 쓴다 |
| 자료 표시 | 없는 이미지와 내용을 지어내지 않고 표시한다 |
| 원본 보존 | 원본을 그대로 두고 복사본에서 작업한다 |

## 8. 알아 둘 제약

`slot-map.json`에는 현재 6장과 8장 매핑만 들어 있다. 2장과 3장은 매핑 없이 `page-catalog.md` 설명과 원본을 보고 진행해야 한다. 실습에는 지장이 없지만, 내 템플릿으로 옮길 때는 **쓸 장을 하나도 빠뜨리지 말고 매핑해 두는 편이 낫다.**

매핑의 shape ID는 슬라이드 안에서만 유효하고 원본 파일 버전이 바뀌면 달라진다. `page-catalog.md`에 적힌 SHA-256과 지금 파일이 같은지 먼저 맞춰 보면 버전이 바뀐 것을 바로 잡을 수 있다.

## 9. 막히면

| 증상 | 확인할 것 |
|---|---|
| Skills 메뉴가 없다 | 조직 정책과 내 역할 권한 |
| 업로드가 거부된다 | 압축 맨 위가 `company-ppt-library` 폴더인지 |
| 장수가 3장이 아니다 | "표지와 마무리 없이 본문 3장"을 적었는지 |
| 원본 장과 결과 장을 섞는다 | "원본 2장"처럼 원본임을 명시했는지 |
| 8장을 이미지 3개로 쓴다 | 합성 이미지라는 점을 다시 확인시킨다 |
| PPT 파일이 안 나온다 | Settings → Capabilities의 코드 실행·파일 생성 |

## 10. 실습이 끝나면

`company-ppt-library` 토글을 끈다.

내 회사 템플릿이 이 유형인지 판별하는 법과 카탈로그·슬롯맵을 직접 만드는 요령은 `Claude_PPT_skill_4케이스_안내.pptx`의 팁 슬라이드에 정리해 두었다. 레이아웃이 두세 개뿐인데 슬라이드가 훨씬 많다면 이 케이스의 방식으로 접근하면 된다.
