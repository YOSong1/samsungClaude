# Case 02. skill 등록과 사용자 요청 흐름

## 학습 목표

skill을 등록하고 구성안·수정·제작 요청을 구분한다.

## 개념 설명

skill은 재사용 지침이며 파일 생성 도구 자체가 아니다. ZIP에는 SKILL.md와 템플릿을 함께 넣는다. 웹·데스크톱 등록과 Claude Code의 로컬 경로 설치를 구분한다. 현재 대화의 최신 구성안을 반영하는 후속 요청이 핵심이다. 생성하지 않은 PPT를 완료로 취급하지 않는다.

## 파일 안내

- 실제 지침: [company-ppt-workflow/SKILL.md](company-ppt-workflow/SKILL.md)
- 템플릿 원본 복사본: [company-ppt-workflow/assets](company-ppt-workflow/assets)
- 업로드용 패키지: [company-ppt-workflow.zip](company-ppt-workflow.zip)
- 이 케이스만 보고 따라 하는 절차: [등록_및_활용.md](등록_및_활용.md)
- 네 케이스 한눈에 보기: [Claude_PPT_skill_4케이스_안내.pptx](../Claude_PPT_skill_4케이스_안내.pptx)
- 공통 등록 설명: [등록·사용 가이드](../00_강의자료/등록_사용_가이드.md)

이 skill은 대화에서 설명한 설계를 실제 파일로 정리한 교육용 버전이다. 제공 템플릿은 사용자 원본의 바이트 동일 복사본이다. 실제 Claude 계정 설치와 Claude에서의 PPT 생성 성공 여부는 아직 검증하지 않았다.

## 실습 순서

1. SKILL.md를 열어 설명과 작업 범위를 읽는다.
2. assets의 PPT를 열어 레이아웃과 실제 슬라이드를 비교한다.
3. 해당 ZIP 하나를 등록하고 정확한 skill 이름으로 요청한다.
4. 아래 프롬프트를 입력한다.
5. 기대 동작과 비교한다. 구성안을 수정하고 원하면 PPT 제작을 요청한다.

```text
company-ppt-workflow skill을 사용해 사내 생성형 AI 시범 도입 방안을 임원용 8장으로 정리해줘. 먼저 요구사항과 구성안만 보여줘. 자료에 없는 예산과 효과 수치는 확인 필요로 표시해줘.
```

## 해설과 평가

첫 응답에 파일 생성을 요구하지 않았으므로 구성안에서 멈춰야 한다. 수정 후 제작을 요청하면 최신 수정본을 사용한다. 파일 생성 도구가 없으면 구성안을 제공하고 제한을 밝혀야 한다.

평가 항목: 사용자 범위 준수, 올바른 파일 선택, 페이지 구조 일치, 근거 없는 정보 미생성, 실제 파일 제공 여부, 미검증 항목의 정직한 보고.

## 확장 과제

한글 제목을 길게 바꾸고 항목 수를 하나 늘려본다. 텍스트 축소만으로 처리하는지, 요약·재배치·페이지 변경 등 의미를 유지하는 대안을 선택하는지 살핀다. 고정 장수 조건을 추가하여 다시 비교한다.
