# Case 03 등록과 활용

이 문서 하나만 보고 Case 03을 끝까지 진행할 수 있다. 다른 케이스를 먼저 하지 않아도 된다.

- skill 이름: `company-ppt-router`
- 올릴 파일: `03_여러템플릿_통합선택/company-ppt-router.zip`
- 쓰는 템플릿: 발표템플릿1.pptx와 발표템플릿2.pptx, 두 개

실무에서 템플릿이 하나뿐인 경우는 드물다. 이 케이스는 skill 하나가 여러 템플릿 중 맞는 것을 고르게 하는 구조를 다룬다. 네 케이스 중 실무 출발점으로 삼기 좋은 쪽이다.

## 1. 준비

`company-ppt-router.zip`을 내려받아 압축을 열어 본다. 맨 위가 `company-ppt-router` 폴더이고 그 바로 아래에 `SKILL.md`가 있어야 한다. 이 케이스는 템플릿 두 개가 들어 있어 파일이 6MB가 조금 넘는다.

```
company-ppt-router/
  SKILL.md
  assets/발표템플릿1.pptx
  assets/발표템플릿2.pptx
  references/template-catalog.md      선택 기준
  references/template1.md             템플릿1 다루는 법
  references/layout-catalog.md        템플릿1 레이아웃 목록
  references/template1-inventory.json
  references/template2.md             템플릿2 다루는 법
  references/page-catalog.md          템플릿2 페이지 목록
  references/template2-inventory.json
  references/slot-map.json
  scripts/inspect_pptx.py
```

`template1`, `template2`는 이 패키지가 두 파일에 붙인 이름이다. Claude에 템플릿을 따로 등록하는 기능이 있는 것이 아니다.

## 2. 등록하는 곳은 두 군데다

| 등록 위치 | 이걸 보는 것 |
|---|---|
| claude.ai 계정 | Claude 웹, 데스크톱 앱 |
| 내 PC의 파일 | Claude Code (터미널) |

웹과 데스크톱은 같은 계정 저장소를 본다. 한 번 올리면 둘 다에서 쓸 수 있고 따로 등록하지 않는다.

Claude Code는 저장소가 다르다. 다만 claude.ai 계정으로 로그인한 세션이면 계정 skill을 `~/.claude/skills/synced/` 아래로 자동으로 내려받는다. 이때는 아래 2-B를 따로 하지 않아도 된다. API 키나 환경변수로 인증했거나 조직 정책이 막아 둔 세션에서는 동기화가 되지 않으므로 2-B로 직접 설치한다.

2-A와 2-B를 둘 다 하면 같은 skill이 두 벌이 되어 어느 쪽이 걸릴지 갈린다. 하나만 한다. 계정에 올린 뒤 Claude Code에서 `/company-ppt-router`가 보이는지로 동기화 여부를 판단하면 된다.

## 2-A. Claude 웹·데스크톱에 등록

1. Customize → Skills → **+** → Create skill → **Upload a skill**
2. `company-ppt-router.zip`을 ZIP 그대로 올린다.
3. `company-ppt-router` 토글을 켠다.
4. **다른 케이스 skill은 모두 끈다.** 01·02·04를 같이 켜 두면 어느 skill이 걸릴지 갈려서 이 케이스의 선택 동작을 볼 수 없다.
5. Settings → Capabilities에서 코드 실행과 파일 생성을 켠다.

## 2-B. Claude Code에 설치

ZIP을 풀어 `company-ppt-router` 폴더를 통째로 복사한다.

- 계정 전체: `%USERPROFILE%\.claude\skills\company-ppt-router\`
- 프로젝트 한정: 그 프로젝트의 `.claude\skills\company-ppt-router\`

다른 케이스 폴더가 같은 위치에 있으면 실습하는 동안 치워 둔다.

## 3. 첫 요청 — 템플릿을 지정하지 않는다

이 케이스의 핵심 동작을 보려면 어떤 템플릿을 쓸지 일부러 말하지 않는다.

```text
company-ppt-router skill을 사용해 '신입사원 사내 시스템 사용법'을 구성해줘.
화면과 단계 설명 중심이므로 등록된 템플릿 중 적합한 것을 선택하고 이유를 알려줘.
6장 구성안만 먼저 제시해줘.
```

화면과 단계 중심이라고 했으니 template2 쪽이 자연스럽다. 다만 고른 결과보다 **고른 이유를 말하는지**가 더 중요하다.

## 4. 제대로 걸렸는지 확인

참고자료를 읽어야만 알 수 있는 것을 되묻는다.

```text
고른 템플릿의 실제 파일 경로와 처리 방식을 적어줘.
그 템플릿의 레이아웃이 몇 개인지도 알려줘.
```

`assets/발표템플릿2.pptx`, `slide-library`, `레이아웃 3개` 같은 답이 나오면 카탈로그를 읽은 것이다. 파일 이름을 지어내거나 처리 방식을 얼버무리면 걸리지 않았다.

참고로 두 템플릿은 이렇게 다르다.

| | template1 | template2 |
|---|---|---|
| 파일 | 발표템플릿1.pptx | 발표템플릿2.pptx |
| 슬라이드 | 12장 | 9장 |
| 레이아웃 | 15개 | 3개 |
| 처리 방식 | master-layout | slide-library |
| 맞는 내용 | 일반 발표, 비교, 여러 열, 사진 배치 | 사용법, 단계 설명, 화면 중심 교육 |

## 5. 두 번째 요청 — 사용자 지정이 이기는지

같은 주제로 이번에는 템플릿을 못 박는다.

```text
같은 주제를 template1으로 다시 구성해줘. 6장 구성안만.
```

앞에서 template2가 낫다고 했더라도 사용자가 지정하면 그 지정을 따라야 한다. 판단을 고집하면 안 된다. 다만 template1에서는 단계 설명이 어떻게 달라지는지 같이 설명하면 좋은 답이다.

## 6. 세 번째 요청 — 없는 형식을 물을 때

```text
여기에 도입 비용을 항목별로 비교하는 표 한 장을 추가해줘.
```

두 템플릿에 딱 맞는 비용 비교 페이지가 없을 수 있다. 이때 억지로 기존 페이지에 밀어 넣는지, 적합한 원본이 없다고 설명하고 대안을 제시하는지 본다.

## 7. 확인 항목

| 확인할 것 | 통과 기준 |
|---|---|
| 선택 | 고른 템플릿과 이유를 함께 말한다 |
| 근거 | 실제 파일 경로를 답한다 |
| 우선순위 | 사용자가 지정하면 그 지정을 따른다 |
| 한계 | 맞는 원본 페이지가 없으면 없다고 말한다 |
| 범위 | 구성안만 요청했으면 구성안에서 멈춘다 |

## 8. 이 케이스에서 짚을 것

디자인과 레이아웃이 다른 정도는 이렇게 skill 하나에 템플릿별 참고 파일을 두어 관리하면 된다.

반면 요구사항을 받는 방식, 반드시 넣어야 하는 항목, 검토 절차가 크게 다른 업무라면 skill을 나누는 편이 낫다. 갈림길은 파일 개수가 아니라 업무 절차가 다른지 여부다.

## 9. 막히면

| 증상 | 확인할 것 |
|---|---|
| Skills 메뉴가 없다 | 조직 정책과 내 역할 권한 |
| 업로드가 거부된다 | 압축 맨 위가 `company-ppt-router` 폴더인지 |
| 엉뚱한 skill이 걸린다 | 01·02·04 토글을 껐는지 |
| 이유 없이 템플릿을 고른다 | 요청에 "이유를 알려줘"를 넣었는지 |
| 없는 템플릿을 말한다 | 등록된 파일은 두 개뿐이라고 다시 알려 준다 |
| PPT 파일이 안 나온다 | Settings → Capabilities의 코드 실행·파일 생성 |

## 10. 실습이 끝나면

`company-ppt-router` 토글을 끈다.

내 회사 템플릿에 같은 방식을 옮기는 요령은 `Claude_PPT_skill_4케이스_안내.pptx`의 팁 슬라이드에 정리해 두었다. 실무에서 템플릿을 여러 개 쓴다면 이 케이스의 `references/template-catalog.md` 구조를 그대로 가져다 쓰면 된다.
