## 권장 구조

하나의 회사 발표 skill에 템플릿별 adapter 안내를 두고, 이 템플릿에는 slide-library 방식을 적용한다. 이는 구현을 위한 자체 분류이며 Claude의 내장 설정 키가 아니다.

```text
company-presentation/
  SKILL.md
  assets/
    template2/source.pptx
    template2/library.pptx
  references/
    template-catalog.md
    template2/page-catalog.md
    template2/slot-map.json
    template2/content-rules.md
  scripts/
    inspect-template.*
    build-deck.*
    validate-deck.*
```

위 구조는 향후 구현안이다. 현재 library.pptx, 생성·검증 스크립트, 등록 가능한 skill ZIP은 제작하지 않았다.

## 실행 원칙

1. 사용자 요청을 목적, 청중, 장수, 근거 자료, 필수 메시지로 정리한다.
2. 슬라이드별 내용의 관계를 분류한다: 설명, 순서, 병렬 항목, 비교, 추세, 계층 등.
3. 페이지 카탈로그에서 내용 관계와 항목 수에 맞는 예시 슬라이드를 고른다.
4. title/body/images 등 필드가 채워진 구성안을 만든다. 시각 자료가 없으면 상태를 표시한다.
5. 원본 또는 정비된 라이브러리의 해당 슬라이드를 복제한다.
6. 정해진 개체만 교체하고 서식, 그룹 좌표, 크롭, 미디어 및 링크 관계를 유지한다.
7. 텍스트 길이는 글자 수와 실제 렌더링으로 검증한다. 제목 1줄·본문 2~3줄 등의 목표는 페이지별로 시험한 후 확정한다.
8. 지원하지 않는 표·차트·비교 페이지를 기존 이미지 페이지에 억지로 배치하지 않는다. 새 유형을 정의하거나 적합한 다른 승인 템플릿을 사용한다.
9. 정적 렌더링뿐 아니라 요구된 편집 가능성, 링크, 동영상, 자막, 전환 기능을 별도 확인한다.

## 구현 시 특히 주의할 점

- '내용 개체 틀 17'이라는 이름이 여러 개 반복되고 실제 개체 틀이 아닌 일반 도형도 있다. 이름만으로 치환하지 않는다.
- 복제용 라이브러리에서 의미 있는 고유 이름(title, item_1_description 등)을 부여하고 버전을 관리하면 안정성이 높아진다.
- 텍스트는 굵기·색상 등이 다른 여러 run으로 나뉘므로 XML 문자열 전체 치환으로 서식을 손상시키지 않는다.
- 원과 숫자만 그룹인 경우가 많다. 그룹 하나를 이동해도 본문과 그림은 따라오지 않는다.
- 그림 속 UI 문구는 원본 이미지 자체를 교체해야 바뀐다.
- 여러 슬라이드가 동일 media를 참조할 수 있다. 한 페이지만 교체하려면 새로운 media와 관계를 만들어 다른 페이지를 변경하지 않는다.
- 슬라이드 XML만 복사하면 이미지·노트·영상·자막·링크 관계를 놓칠 수 있다. 패키지 관계를 함께 처리하는 복제 방법이 필요하다.
- 원본에는 12pt 본문 설정과 직접 서식이 있다. '원본과 동일'과 '발표장 가독성'은 별도 기준으로 결정한다.
- 모든 형식을 마스터로 옮기지 않는다. 고정 공통 장식은 마스터에, 반복 배치는 레이아웃에, 편집할 콘텐츠와 복잡한 페이지 구성은 슬라이드에 둔다.
