# Case 01 등록과 활용

이 문서 하나만 보고 Case 01을 끝까지 진행할 수 있다. 다른 케이스를 먼저 하지 않아도 된다.

- skill 이름: `company-ppt-master`
- 올릴 파일: `01_마스터기반_템플릿/company-ppt-master.zip`
- 쓰는 템플릿: 발표템플릿1.pptx (12장 / 마스터 1개 / 레이아웃 15개)

## 1. 준비

`company-ppt-master.zip`을 내려받아 압축을 한 번 열어 본다. 맨 위에 `company-ppt-master` 폴더가 있고 그 바로 아래에 `SKILL.md`가 보여야 한다. 다른 모양이면 등록해도 걸리지 않는다.

```
company-ppt-master/
  SKILL.md
  assets/발표템플릿1.pptx
  references/layout-catalog.md
  references/template-inventory.json
  scripts/inspect_pptx.py
```

## 2. 등록하는 곳은 두 군데다

| 등록 위치 | 이걸 보는 것 |
|---|---|
| claude.ai 계정 | Claude 웹, 데스크톱 앱 |
| 내 PC의 파일 | Claude Code (터미널) |

웹과 데스크톱은 같은 계정 저장소를 본다. 한 번 올리면 둘 다에서 쓸 수 있고 따로 등록하지 않는다.

Claude Code는 저장소가 다르다. 다만 claude.ai 계정으로 로그인한 세션이면 계정 skill을 `~/.claude/skills/synced/` 아래로 자동으로 내려받는다. 이때는 아래 2-B를 따로 하지 않아도 된다. API 키나 환경변수로 인증했거나 조직 정책이 막아 둔 세션에서는 동기화가 되지 않으므로 2-B로 직접 설치한다.

2-A와 2-B를 둘 다 하면 같은 skill이 두 벌이 되어 어느 쪽이 걸릴지 갈린다. 하나만 한다. 계정에 올린 뒤 Claude Code에서 `/company-ppt-master`가 보이는지로 동기화 여부를 판단하면 된다.

## 2-A. Claude 웹·데스크톱에 등록

1. Claude를 연다.
2. Customize → Skills → **+** → Create skill → **Upload a skill**
3. 내려받은 `company-ppt-master.zip`을 고른다. 압축을 풀지 않고 ZIP 그대로 올린다.
4. 목록에 생긴 `company-ppt-master`의 토글을 켠다.
5. Settings → Capabilities에서 **코드 실행**과 **파일 생성**을 켠다. PPT 파일을 받으려면 필요하다.

Skills 메뉴 자체가 없으면 조직이 사용자 skill 생성을 막아 둔 것이거나 내 역할에 권한이 없는 경우다. 관리자에게 확인한다.

## 2-B. Claude Code에 설치

ZIP을 풀어서 `company-ppt-master` 폴더를 통째로 아래 위치에 복사한다.

- 내 계정 전체에서 쓰려면: `%USERPROFILE%\.claude\skills\company-ppt-master\`
- 특정 프로젝트에서만 쓰려면: 그 프로젝트의 `.claude\skills\company-ppt-master\`

복사한 뒤 `SKILL.md`가 `...\skills\company-ppt-master\SKILL.md` 위치에 있으면 맞다. 폴더가 한 겹 더 들어가 `company-ppt-master\company-ppt-master\`가 되면 안 된다.

이 저장소를 내려받은 것만으로는 설치되지 않는다. `01_마스터기반_템플릿` 폴더는 skill 경로가 아니다.

## 3. 첫 요청

```text
company-ppt-master skill을 사용해 '신입사원 온보딩 개선' 구성안을 총 3장으로
정리해줘. 표지, 현행과 개선안 비교, 세 가지 실행 과제로 구성하고
발표템플릿1의 레이아웃을 지정해줘. 이번에는 구성안만 작성해줘.
```

## 4. 제대로 걸렸는지 확인

구성안이 그럴듯하게 나왔다는 것만으로는 판단할 수 없다. 요청문에 이미 3장 구성이 들어 있기 때문이다. 참고자료를 읽어야만 알 수 있는 값을 되묻는다.

```text
각 장에 고른 레이아웃의 이름과 개체 틀 idx를 같이 적어줘.
```

`제목 슬라이드 / 비교 / 3 열` 같은 실제 레이아웃 이름과 `title:0, body:32, obj:1` 같은 idx가 나오면 `references/layout-catalog.md`를 읽은 것이다. 레이아웃 이름을 지어내거나 "제목 및 내용"만 반복하면 걸리지 않았거나 읽지 않은 것이다.

참고로 발표템플릿1의 레이아웃 15개는 다음과 같다.

제목 슬라이드 / 제목만 / 감사 슬라이드 / 제목 및 내용 / 내용 2개 / 3 열 / 큰 사진 / 비교 / 콘텐츠 사진 3 / 구분선 슬라이드 1 / 구분선 슬라이드 2 / 콘텐츠 사진 1 / 콘텐츠 사진 2 / 비어 있음 / 5 열

## 5. 이어서 해 볼 것

구성안을 고친 다음 파일 제작을 요청한다.

```text
지금 구성안에서 실행 과제를 네 개로 늘려줘. 총 3장은 그대로 두고.
그 다음 편집 가능한 PPT로 만들어줘. 원본은 그대로 두고 결과 파일을 줘.
```

세 항목짜리 `3 열` 레이아웃에 네 번째를 어떻게 넣는지 본다. 글자만 줄여 억지로 밀어 넣는지, `5 열`이나 `제목 및 내용`으로 바꾸거나 장을 나누자고 하는지가 갈린다.

## 6. 이 케이스에서 짚을 것

마스터는 공통 서식, 레이아웃은 페이지 배치, 슬라이드는 내용이다. 셋을 구분해야 "제목 및 내용"만 반복해서 쓰는 습관에서 벗어난다.

레이아웃을 고른다고 예시 슬라이드의 표와 차트가 따라오지는 않는다. 발표템플릿1에서 차트 3개는 8장에, 표 1개는 9장에 들어 있고 두 장 모두 `제목만` 레이아웃을 쓴다. 표와 차트는 그 슬라이드의 개체이지 레이아웃이 주는 것이 아니다.

마스터가 있다는 것과 서식이 제대로 상속된다는 것도 다른 이야기다. 슬라이드에 직접 준 서식이 상속을 덮어쓸 수 있다.

## 7. 막히면

| 증상 | 확인할 것 |
|---|---|
| Skills 메뉴가 없다 | 조직 정책과 내 역할 권한 |
| 업로드가 거부된다 | 압축 맨 위가 `company-ppt-master` 폴더인지 |
| 반응이 평소와 같다 | 요청문에 `company-ppt-master`를 그대로 넣었는지 |
| 다른 템플릿을 고른다 | 다른 케이스 skill을 같이 켜 두지 않았는지 |
| PPT 파일이 안 나온다 | Settings → Capabilities의 코드 실행·파일 생성 |
| 파일을 못 읽는다고 한다 | 경로만 적지 말고 파일을 직접 첨부했는지 |

## 8. 실습이 끝나면

다음 케이스로 넘어가기 전에 `company-ppt-master` 토글을 끈다. 여러 개를 켜 두면 어느 skill이 걸릴지 갈린다.

내 회사 템플릿에 같은 방식을 옮기는 요령은 `Claude_PPT_skill_4케이스_안내.pptx`의 팁 슬라이드에 정리해 두었다.
